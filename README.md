# Super Mech

An unofficial fan-made mech game prototype built with **Godot 4.6 .NET** and **C#**.

The project now opens into a local workshop prototype. It supports browsing a small project-authored component catalogue, equipping one component per slot, viewing derived build statistics, and saving a build locally. The old preassembled mech preview scene remains available as \`player_mech.tscn\`.

This is an evolving prototype, not a finished or verified 1-to-1 recreation of the original game. The sample workshop data uses original prototype names and balance values; it is not represented as the original game's item database.

## Requirements

- Godot **4.6 .NET** editor build
- .NET SDK **8.0** for desktop development
- Git

Use the .NET edition of Godot; the standard editor cannot build C# scripts.

## Clone and open

\`\`\`bash
git clone https://github.com/Adeeb-muhammad/Super-Mech-.git
cd Super-Mech-
\`\`\`

Open \`project.godot\` in Godot 4.6 .NET and allow the editor to import the project and build the C# assembly. The default run scene is \`Scenes/Workshop/workshop.tscn\`.

## Build and test

From the repository root:

\`\`\`bash
dotnet restore "super mech.csproj"
dotnet build "super mech.csproj"
dotnet test "Tests/Tests.csproj"
\`\`\`

The test project targets .NET 8 and links only the pure workshop-domain sources. It does not load Godot or depend on editor source generators.

## Workshop prototype

- Four non-combat equipment slots: Frame, Mobility, Core, and Utility.
- One item per slot; Frame and Mobility are required for a ready build.
- A small, original local catalogue with explicitly labelled prototype balance values.
- Live derived statistics and build-budget validation.
- Versioned JSON loadout data saved to \`user://mech_loadout.json\`.
- An original vector preview generated by Godot drawing primitives; no additional third-party artwork is copied into the workshop.

The initial catalogue is a starter data set for developing the workshop flow. It is not an exhaustive inventory or a claim of exact source-game stats.

| Path | Responsibility |

| \`Scripts/Mech/Workshop/\` | Workshop catalogue, loadout codec, local persistence, screen, and vector preview |
| \`Scripts/Mech/\` | Godot mech resources, assembly, validation, and stat aggregation |

| \`AGENTS.md\` | Development and repository-maintenance instructions |

## Architecture notes

- \`MechStatManager\` is registered as an autoload at \`/root/MechStatManager\`.
- The workshop prototype's \`BuildCost\` is a build-budget value, separate from \`EnergyCapacity\`.
- Workshop loadouts are stored by stable part IDs and slot names rather than by sprite paths or scene NodePaths.
- \`WorkshopLoadoutCodec\` owns JSON version checks and validation; \`WorkshopSaveStore\` owns only local \`user://\` file I/O.
- The existing \`MechPart\` / \`MechAssembler\` resource path remains in place as a separate legacy assembly prototype. The new workshop is data-driven and does not yet convert the old static preview scene into a saved loadout.
- The current workshop is local/offline. Online accounts, server inventories, campaign rewards, matchmaking, and progression are not implemented.
